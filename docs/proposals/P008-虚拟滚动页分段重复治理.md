# P008 · 虚拟滚动页(飞书超长文档)分段重复治理

| 状态 | **已实现,待用户实测**(方案一+二,v0.8.9,2026-09-16) |
|---|---|
| 提案日期 | 2026-09-16 |
| 前置 | P003 分段捕获 + v0.4.5 预热;CDP 笔记样本 2(飞书 17693px 实测诊断) |
| 目标 | 飞书类虚拟滚动长文档分段截图消除「中段重复」,段缝内容连续 |

## 1. 现象与实测依据

用户实测(2026-09-16,Edge/Chrome 152 @ macOS,dpr 1):

- 页面:飞书超长文档,内部滚动容器 `div.bear-web-x-container`,容器内容高
  **17693px**,视口 934px(诊断 JSON 已归档 CDP 笔记样本 2);
- 症状:成图**中间部分重复截取**;
- 关键观察:滚动过程中进度条**一段一段加载、总长越滚越长**(内容流式加载 +
  虚拟列表块高估算值被实测值逐步替换)。

## 2. 根因分析

1. 总高 17693 + 头部偏移 64 + 余量 16 ≈ **17773 CSS px > 单边上限 16000**
   (v0.4.2 实测硬约束)→ 必走**分段路径**(chunkHeight 4000,约 5 段、4 条缝);
2. 分段按 `scrollTop = pos` 定位。现有复核(v0.4.1)只锁 **scrollTop 数值**,
   不锁**内容身份**:已截区域的块高一旦被实测值替换(或新内容流入),
   后续内容整体下移,下一段在 `pos` 处拍到的仍是上一段尾部 → **段间重复**;
3. 自动滚动只在触底时做 2×600ms 的增长检查(v0.2.1),无法保证
   「全文档高度已收敛」——用户观察到的「越滚越长」正是未收敛的直接证据。

结论:**段间重复 = 内容在捕获期间沿纵向漂移,而定位基准(scrollTop 数值)没有跟着内容走。**

## 3. 方案

### 方案一:高度收敛门控(低成本,解决「总高还在长」)

`runAutoScroll` 结束后、计算 capH 之前,加收敛循环:

- 轮询 `RENDER_STABLE` + `METRICS`(容器 scrollHeight),**连续两轮相等**才算收敛;
- 若增长:回底再滚一轮(触发剩余懒加载),重新计;
- 上限 6 轮 / 约 20s 兜底,超时按当前高度继续并在 notes 明示「高度未完全收敛」。

### 方案二:段间内容锚定(核心,消除段间重复)

content 侧新增锚点读取,分段循环每段:

1. 定位后记录**视口顶部第一个稳定块**的标识(飞书块带 `data-record-id` 类
   属性;取不到则用「块在容器块序列中的索引」)及其精确内容偏移;
2. 拍下一段前重查该锚块的当前内容偏移;若发生漂移,用锚块新位置修正段起点
   (`pos = 锚块新偏移 + 段内原偏移`),把上方长高的位移吃掉;
3. 锚块消失(虚拟列表回收)时降级为现有 scrollTop 复核逻辑。

效果:定位基准从「数值」变成「内容」,上方漂移被逐段吸收,段缝连续。

### 方案三:重叠拍摄 + 像素去重拼接(不推荐)

每段多拍 ~200px,拼接端模板匹配去重。长页自动转 JPEG,像素匹配模糊不可控;
拼接端改动大且脆。放弃。

### 方案四:虚拟列表物化(不推荐作为首选)

把容器 style 撑高到 scrollHeight 强制全量渲染,再分段拍。侵入页面运行时布局,
飞书渲染管线未知副作用多,可能直接破坏页面。仅在一+二失败后重议。

## 4. 建议

**方案一 + 方案二组合**:一保证起点高度收敛(消灭大部分漂移源),二在残余
漂移下逐段校正(兜底)。两者都在现有「先仿真后滚动」纪律内,不引入新坐标系。

## 5. 改动面(预估)

| 文件 | 动作 |

## 6. 验收(用户实测)

1. 同一篇 17693px 飞书文档整页截图:中段无重复、段缝内容连续;
2. 普通长页(无虚拟滚动)回归:结果与 v0.8.8 逐像素一致;
3. 无限流页:收敛循环不挂死,超时路径正常出图并带提示。
