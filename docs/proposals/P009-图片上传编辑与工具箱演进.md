## 1. 需求拆解

- **本期(必须)**:上传单张/多张图片 → 打开预览 Tab → 每张图独立用现有编辑器标注 → 复制/下载。
- **顺带(低成本高价值)**:下载面板加「格式 + 质量」选项 = 转格式 + 压缩两个工具(浏览器 canvas 转码零依赖)。
- **后续分期**:剪裁(P007 §4 已列候选)、多图合并(竖拼/横拼/网格)、右键菜单直达、UI 重整。

## 2. 入口方案(请拍板)

| 方案 | 形态 | 优点 | 缺点 |
|---|---|---|---|
| **A. popup 面板按钮(推荐)** | 截图按钮区下方加「图片」分区:「打开图片编辑…」(系统文件框,可多选) | 主入口唯一,不学新位置;popup 本来就是扩展门面 | 多点一次图标 |

## 3. 本期技术方案(最大化复用,零新依赖)

### 3.1 上传链路

```
popup 文件框(accept="image/*", multiple)
  → FileReader 读 blob → base64 分块(512 KB,同 imagestore 协议)
  → 新消息 cs/upload.begin{mime,name,size} → sw 建上传会话
  → cs/upload.chunk{b64} × N → cs/upload.done
  → sw:imagestore.put(jobId, meta) → chrome.tabs.create(preview?job=...)
```

- 复用 `imagestore`(TTL 10 分钟、≤3 job 现状不变);**单文件上限 50 MB、
  单批总上限 150 MB**,超限在 popup 直接报错不入 SW;
- 浏览器可解码的格式都可上传(PNG/JPEG/WebP/GIF/BMP/AVIF);
- GIF/AVIF 动图按首帧处理(编辑器本就是静态标注,注记明示)。

### 3.2 多图呈现:meta 加 `items[]`

- 现状 meta = 单图(单张/分段/分卷)。上传多图时
  `meta.items = [{mime,name,widthPx,heightPx,segments}, ...]`;
- preview 检测到 `items` 走**列表模式**(复用分卷列表的 DOM 与
  edit.js 多 target 能力——编辑器本来就是多 target 设计,每图独立 store);
- 每张图各自「复制/下载/编辑」;顶部全局按钮退化为「全部下载(打包逐个触发)」或仅保留信息栏,具体以实现稿为准。

### 3.3 转格式 + 压缩(下载面板)

- preview 头部下载按钮改为「下载 ▾」小面板:**格式**(原始/PNG/JPEG/WebP)+
  **质量**(JPEG/WebP 时显示,60–100)+ **缩放**(100%/75%/50%,= 压缩体积的另一旋钮);
- 无标注时走 canvas 重编码(不再是原 blob 直通)——仅当用户改了选项时才重编码,
  默认行为零回归;
- 合成/转码全在 preview 页 canvas 完成,不经 SW。
