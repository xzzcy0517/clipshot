# P003 · 超长页治理方案(总长上限 / 单图上限 / 分卷 / 桥多段修复)

| 状态 | 草案 v1 · 待用户确认 |
|---|---|
| 提案日期 | 2026-09-11 |
| 触发 | 用户实测:17756px 飞书文档;dpr=2 时总面积 132M 超 60M 上限走分段;Agent 拿到的"长图"实际只有第一段(真 bug);浏览器预览因合成超画布只能逐段下载 |
| 关联 | `background/pipeline.js`、`bridge/relay.mjs`、`bridge/mcp.mjs`、`preview/preview.js`、`common/geom.js`、options 设置页 |

## 0. 两个根因(先讲清楚,方案才站得住)

**① 桥多段损坏(必须修的 bug,与"长"无关)**
`deliver`→`imagestore` 分块回传时,chunk 携带 `seg` 段号,但 relay 侧
`upload` 处理把所有段的 base64 按 seq **直接连成一个文件**。PNG/JPEG 解析器遇到
第一段尾部数据即停止/判损坏 → Agent 读到的"图"只有第一段(≈一个分段高度的内容),
**看起来就是"丢弃了很多"**。分段模式下这条路一直是坏的,此前没被测到是因为
验收页都在 dpr=1 下走了整幅路径。

**② 超长页治理缺失(体验问题)**
- dpr=2 让 17756px 页的面积直接爆 60M 自设上限 → 跳过整幅;但其实**用降分辨率
  整幅**(仿真 deviceScaleFactor 取 1 而非 2,面积 33M)就能拿到一张完整长图;
- 分段后总设备高 35512px > 浏览器 canvas 32767 上限 → 预览合成必然失败 →
  逐段下载,人看着像"截坏了";
- 总长度目前只有滚动行程保护(maxScrollPx=30000),**捕获侧没有总长上限**,
  理论上可以截一张无限长的碎图串;
- 5 条黄条提示重复啰嗦(每条路径各喊一句)。

## 1. 治理规则(三层上限,全部进设置页可调)

```
页面总高 capW/capH(现有,内部容器感知)
  │
  ├─ 总长闸门  maxTotalCssH(新,默认 60000 CSS px)
  │     超出 → 只截前 maxTotalCssH,注记「已按总长上限截取前 N px,后续未截」
  │     (截断出可用结果 + 明示,而不是直接失败;滚动阶段同样受此约束)
  │
  ├─ 整幅优先(新,自动,无开关)
  │     仿真整幅所需 deviceScaleFactor = min(dpr, sqrt(AREA_CAP/(capW*capH))),下限 1
  │     → dpr2 的 17756px 页面积 33M ≤ 60M,直接一张完整长图,回到整幅路径
  │
  └─ 整幅不可行才分段
        单图上限  maxPartDeviceH(新,默认 12000 设备px)
        chunkHeight 自动收敛 = min(设置值, floor(maxPartDeviceH/实际输出倍率))
        → 保证每一段都远低于纹理/canvas 限制,段段可用
```

## 2. 分卷输出(替代「逐段下载」的断链体验)

目标:任意长度的页,人和 Agent 拿到的都是**尽量少的几张"可打开的长图"**。

- **preview 侧**:合成前按各段**实际解码高度**做装箱——每卷累计 ≤ `VOLUME_CAP=30000`
  设备 px;1~2 卷装得下全部 → 每卷一张合成长图(预览分卷标签页 + 逐卷下载);
  只有装箱失败(单段即超限)才退回逐段列表(现状保留作兜底)。
  总高 ≤32767 时维持现有单张合成不变。
- **桥/Agent 侧(修根因①)**:chunk 按 `seg` 分组,**每段落盘一个文件**:
  单段 → `ClipShot_…_full.png`(现状不变);多段 → `_part1.png / _part2.png …`;
  HTTP 响应 `image: { path(=part1), paths:[全部], parts:N }`(向后兼容,旧字段保留);
  MCP 文本块列出全部路径+「按序即整图」提示;relay 侧组装逻辑纯函数化,可服务器测试。
- 设置页新增:总长上限、单图高度上限两项(默认如上;说明文案写人话)。

## 5. 对你那篇 17756px 飞书文档的预期效果(验收标准)

- dpr=2:不再走分段——降尺度整幅一张图(~1857×17756 @ 视情况 scale≈1.3),预览单张可看,Agent 一次拿全;
- 假如未来遇到 >32767 设备 px 的文档:分段 → 自动分 2 卷长图(而非 5 个碎片段);
- Agent 拿到的路径指向**完整可读**的文件(根因①修复后);
- 黄条最多 2 条,说清「怎么截的、卷几份、哪没截到」。
