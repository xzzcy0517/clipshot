| 状态 | **已实现,待用户实测**(v0.10.0,2026-09-20;用户 2026-09-20 会话内拍板「先出方案再实现,执行」) |
|---|---|
| 提案日期 | 2026-09-20 |
| 前置 | P009 多图上传(三期候选「多图合并导出」由本提案以自由布局先行覆盖);P012 右下角统一面板与选中模型 |
| 目标 | 预览 Tab 变画板:图片可拖到任意位置;缩放只走等比(永不变形);下载按画板布局合成最终图 |

## 1. 需求(用户原话要点)

上传多图或截图打开的新 Tab 都变成画板;图片随意拖动位置;导出按画板中图片位置合成;
保留放大缩小且**只能等比缩放**(不许单独改宽高,永不拉变形);编辑标注在画板上照常可用。

## 2. 核心设计

### 2.1 卡片模型

每张图 = `.board-card`(absolute 定位,left/top = 画板 CSS px)+ 悬浮 cap 标签。
`cards[]` 注册表 + `scales` Map(沿用 P012);卡片只存 **位置(x,y)与缩放比 s** 两个布局量,
宽高永远 = `nat/dpr × s` —— 没有独立宽/高入口,物理上杜绝变形。

### 2.2 单图零回归(关键决策)

- **恰好 1 张卡片**(截图/单图上传):s 是**纯视图量**,初始 = 适应宽度(与 v0.9.x 观感一致);
  导出走原路径(无标注原 blob 直通、有标注全分辨率合成 PNG),**逐字节零回归**。
- **≥2 张卡片**(多图上传/分卷/分段):s 成为**布局量**,初始 = 1(自然尺寸,不会暗搓搓缩小);
  导出 = `composeBoard()` 按 bbox 合成 PNG → 喂给 P010 导出弹窗(剪裁/格式/质量/缩放全继承)。

### 2.3 布局与导出数学

- 初始自动纵向堆叠(按 cards 顺序,分卷天然成序);**用户一拖即停自动堆叠**(`boardTouched`);
- 位置钳到 ≥0,容器尺寸 = 卡片 bbox(导出用同一 bbox);画布边 = bbox × dpr,
  s=1 时 1 卡片px = 1 图像设备px,与单图导出同口径;
- 合成时每张卡若有标注先经 `Edit.exportBlob` 合成(natural PNG)再按 s 绘制;
- 超 32767 画布上限 → toast 报错,引导用右下角缩小后再导出(弹窗内缩放滑杆亦可救)。

### 2.4 编辑器零改动

标注坐标存在图像像素系,渲染/命中都读 `getBoundingClientRect` 实时值——
卡片拖动只改 rect,edit.js 不需要任何改动;编辑态拖卡片 = 画标注(卡片不抢),
预览态拖卡片 = 移动(并选中)。

## 4. 验收(用户实测)

1. 多图上传:卡片纵向堆叠打开,拖动任意卡到任意位置,蓝框选中,右下面板缩放等比生效;
2. 下载:弹窗左图 = 画板合成结果(位置/缩放与画板一致),格式/质量/剪裁照常;
3. 单张截图:打开观感、复制/下载产物与 v0.9.6 逐字节一致(零回归);
4. 编辑态标注任意卡片,移动卡片后标注跟随;导出含标注;
5. 双指放大单卡后布局自动重排不重叠(未手动拖过时);超长分卷合成超上限有 toast 提示。

## 5. 明确不做(本期)

画板视图层缩放(看全局用导出弹窗预览代替);卡片删除/旋转/层级;布局 undo;
网格/横拼模板(P009 三期模板候选,自由布局已覆盖主诉求);布局持久化(刷新即重置)。
