# P015 · 手动预热整页截图模式(虚拟滚动页:用户先加载,扩展只拍)

| 状态 | **已实现,待用户实测**(v0.10.5,2026-09-22) |
|---|---|
| 提案日期 | 2026-09-22 |
| 前置 | P008(收敛门控+内容锚点,v0.8.9);CDP 笔记样本 2(飞书 17693px);v0.4.5 预热视口纪律 |
| 目标 | 超长虚拟滚动文档(飞书类)整页截图消除「中段重复」:把「加载」从自动滚动中剥离,交给用户手动完成,扩展只在高度真收敛后拍摄 |

## 1. 背景与现象

- 用户实测:当前版本(v0.10.2,已含 P008 全部治理)截**特别长**的飞书文档时,
  中段仍会出现重复截取。即 P008 的验收项在超长文档上未完全通过。
- 用户提议:新增一种模式——**先在页面上手动把虚拟滚动的内容全部滚出来**
  (滚动条随之收敛到最终长度),再触发截图,期望更准确。

## 2. 根因回顾与用户思路为何成立

「中段重复」的根因链(P008 已定论):

1. 虚拟列表对未渲染块用**估算高度**占位;滚动经过后才替换为**实测高度**,
   总 scrollHeight 随滚动持续增长(用户观察到「进度条越滚越长」);
2. 分段按 `scrollTop` 数值定位;已截区域块高一旦变化,下方内容整体漂移,
   下一段在数值位置拍到上一段尾部 → 段间重复;
3. P008 的两道闸都是**启发式兜底**:收敛门控 6 轮 ≈20s 上限(超长文档可能
   超时放行,notes 提示「未完全收敛」);内容锚点在锚块被虚拟列表回收时
   降级为数值定位。文档越长,两道闸失守概率越大。

**手动预热的价值在「时序」,不在新捕获机制**:

- 用户以人的节奏滚完全文 → 所有块完成「估算→实测」替换、图片懒加载落地,
  **进入捕获前高度已真收敛**,捕获窗口内不再漂移,数值定位重新可靠,
  收敛门控与锚点退化为纯保险丝而不是承重墙;
- 自动滚动(0.75 视口步长 + 350ms settle)本身比人手快得多,既是加载者又是
  扰动源;剥离后,扩展不再「边搅边量」。
- 风险也清楚:用户以为加载完实际没完 → 仍可能重复。因此**收敛快检与锚点
  全部保留**,只换「谁来加载」。

## 3. 方案(推荐)

### 3.1 协议与入口(零协议变更)

- `JOB_START` 已带 `opts` 通道(`{tabId,mode,opts}`),pipeline 会把 opts 并入
  `job.settings`。**不新增 MSG**,协议防漂移测试零改动;
- popup 增加独立按钮(如 `btn-full-manual`,文案示例:「整页截图(手动预热:
  飞书类长文档先把页面滚到底,再点我)」),点击发
  `{ mode:'full', opts:{ prescrolled:true } }`;
- 用**按钮**而非持久设置项:该选择是「按页按次」的决策;若做成
  storage.sync 持久项,用户忘记关 → 普通懒加载页直接截不全,是隐藏陷阱。

### 3.2 pipeline(runFull 内一处分支,差异最小)

`s.prescrolled` 为真时:

1. **跳过**分段预判预热仿真(v0.4.5 的预热是为让自动滚动在拍摄视口下收敛;
   手动模式高度已在真实视口收敛,无需再预热);
2. **跳过** `runAutoScroll`,合成 scrollInfo = 已加载完成;
3. **保留** `waitHeightConverged`(已收敛则一两轮秒过,不耗时;未收敛则照常
   回底逼加载 + notes「页面高度未完全收敛…请先缓慢滚动至文档最底部」);
4. 其后 hideFixed 第二轮、度量、整幅/兼容/分段三段路径、P008 段间锚点
   **全部原样**——只改「谁来加载」,不改「怎么拍」;
5. notes 固定追加「手动预热模式:已跳过自动滚动,仅包含你已加载的部分」;
6. 可选增强:捕获开始与结束各记一次容器 scrollHeight,不一致则 notes 提示
   「捕获期间页面仍在增长,中段可能重复,建议重截」——给失败一个可见信号。

### 3.3 分段路径内的暖机遍历:保留

`runSegmented` 的暖机遍历(拍摄视口下走一遍全文)在手动模式下承担
「验证收敛」角色:已收敛时每步 RENDER_STABLE 秒过,5 段页面仅多几秒;
不另写跳过逻辑,差异最小、回归面最小。

## 4. 边界与风险(如实告知用户)

- **未滚完仍重复**:收敛快检 + notes 提示兜底,但治标文案治不了本,文案必须
  写清操作步骤(从头缓慢滚到底、看到真实底部内容、再点按钮);
- 协作场景(他人实时编辑/评论流入)捕获期间仍可能漂移,锚点兜底;
- 单边 16000 设备 px 硬上限不变:超长文档仍走分段,只是分段从此「站在
  静止的地面上」;
- 无限流页:仅包含已加载部分(notes 明示);
- 本模式对普通 window 滚动页同样安全可用(收敛秒过),只是没有收益。

## 5. 备选方案(记录用,暂不实施)

- **B · 逐屏实拍 + 重叠像素拼接**:真实视口边滚边拍,拼接端模板匹配去重。
  完全不惊扰虚拟列表(零仿真 resize),但要新写拼接/去重管线,P008 方案三
  已因「JPEG 模糊匹配不可控、改动大且脆」否决;手动模式若实测仍不够再复活。
- **C · 慢速精滚自动模式**:自动滚动每步加 RENDER_STABLE 门控,全自动但仍是
  启发式,且超长文档耗时显著;不如手动可靠。
- **D · 虚拟列表物化**:P008 方案四,侵入页面布局,已否决,不重议。

## 7. 验收(用户实测)

1. 同一篇超长飞书文档(17693px 级):先手动从头缓慢滚到底 → 点新按钮 →
   中段无重复、段缝内容连续;
2. 不滚动直接用本模式截懒加载页:只包含已加载部分且 notes 有明示;
3. 普通页回归:原「整页滚动长截图」按钮行为与 v0.10.2 逐像素一致;
4. 按钮文案/操作路径用户看得懂(不用教就会)。
