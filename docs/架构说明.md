# 架构说明

## 模块图

```
popup ─┐ JOB_START / JOB_CANCEL / STATE_GET            预览页 preview
       │        │  (chrome.runtime.sendMessage)          │ IMG_META/CHUNK/DONE
contextMenus ────┼──► background/sw.js ──► pipeline.js ──┼──► imagestore(内存暂存,分块)
                 ┘      (service worker)   │             │
                                           │             └─► tabs.create preview.html?job=…
              ┌────────────────────────────┼───────────────────────┐
              │                            │                       │
        chrome.debugger (CDP)      chrome.tabs.captureVisibleTab   tabs.sendMessage / port
              │                            │                       │
  Emulation.setDeviceMetricsOverride  OffscreenCanvas 裁剪   content.js(滚动/隐藏fixed/
  + Page.captureScreenshot(视口)      (可视区/框选/元素)     拾取/marquee/metrics/定位)
  Page.getLayoutMetrics / Network.*
```

- **classic service worker + importScripts**:零构建下让协议常量(`common/messages.js`)、
  纯函数(`common/geom.js`)在 SW、content、扩展页共用同一份源码的唯一办法。
  content 侧由 manifest `content_scripts.js` 数组保证加载顺序。
- 引擎分工(v0.2.0 重构):整页走 debugger CDP 的**视口仿真捕获**
  (`Emulation.setDeviceMetricsOverride` 放大视口后拍普通截图,DevTools 同款机制;
  失败降级 clip/captureBeyondViewport → 分段仿真);可视区/框选/可滚入视野的元素走
  captureVisibleTab + canvas 裁剪(完全不出现调试横幅;元素路径:视口内直拍 →
  scrollIntoView 后直拍 → 超高元素仿真条带)。

## Service Worker 生命周期与 debugger 防泄漏

Chrome 116+ 起 **活跃的 chrome.debugger 会话会让 SW 保持存活**(官方文档)。
整页流程因此在滚动开始**之前**就 attach —— 会话本身就是保活手段;滚动阶段 port 的
`progress/heartbeat` 消息叠加第二层保活;`alarms` 看门狗兜住未 attach 的等待窗口
(如框选 30s)。

代价是「忘 detach = 横幅常驻 + SW 被自己钉死」,所以有四层清理:

1. 流水线主体 `try { … } finally { cdp.detach() }`;
2. `debugger.onDetach` 监听:用户点横幅「取消」(`canceled_by_user`)→ 标记作业中止,给中文提示,**不重试 attach**;DevTools 抢占(`replaced_with_devtools`)同理;
3. attach 关系写入 `chrome.storage.session`,SW 每次被拉起(顶层代码)/`onStartup`/`onInstalled` 对残留 tabId **盲发 detach** 清扫;
4. `tabs.onRemoved` 清理作业与网络状态。

防重入:`jobsByTab` Map,同 tab 进行中直接 `ERR.BUSY`;跨 tab 并发上限 3(内存保护)。

## 自动滚动协议(port `clip/scroll`)

```
sw ──SCROLL_START{cfg}──► content          content ──connect──► sw 交付 port
content: 每一步 scrollTop 推进 → settleMs → 等待近景图片 → {ev:'stepSettled'}
sw:      CDP Network in-flight 归零保持 300ms → port{cmd:'proceed'}(单步最长 2s 强制放行)
content: 触底后原地等待×2 检测高度增长;连续增长超 maxScrollPx → 判无限流
content: 回顶 → {ev:'atTopDone'} → {ev:'done', infinite, stoppedBy}
sw:      第二轮 hideFixed → SCROLL_TO 0 归零 → getLayoutMetrics+METRICS(容器尺寸)
         → 仿真视口放大 → render.stable → 截图
```

scroller 判定:document 不可滚时,在 `overflow-y: auto|scroll` 且占半屏以上的元素中
取可滚幅度最大者(SPA 内部容器,如飞书文档)。虚拟列表(v0.2.1 起)靠 `cs/render.stable`
渲染稳定门控等占位块换成真实内容;只有「滚动即彻底销毁内容且不留占位」的极端实现
才是结构性限制。

## 捕获与交付

- 整页主路径(v0.2.1):仿真视口放大到内容总高(内部滚动容器页取容器 `scrollHeight`,
  宽度用 `innerWidth` 防滚动条消失重排)→ 等网络空闲 + **渲染稳定门控**
  (`cs/render.stable`,飞书类虚拟列表必需)→ 普通视口截图。
  `captureBeyondViewport` 已降级为旧内核兜底(实测新内核只渲染第一屏,见 CDP 笔记);
  **绝不传 `fromSurface:false`**(会使 clip/captureBeyondViewport 被忽略,Chromium issue 40760789)。
- **P003 三层上限**(v0.4.0,参数全在设置页):
  ① 总长闸门 `maxTotalCssH`(默认 60000 CSS px):超出截前段并在注记明示,绝不无限截;
  ② 整幅仿真**只允许原生 dpr、禁止分数缩放**(v0.4.2 实测:单边超 16384 纹理上限时
  输出尺寸对但尾部回绕成首屏;v0.4.3 实测:0.9× 分数缩放 + 超大视口后半程栅格
  撕裂——两者几何校验都防不住)。`geom.pickEmulationScale` 因此只在「原生 dpr 下
  单边 ≤16000 且面积 ≤60M」时放行单张,否则返回 0 → 分段(人看的单张由 preview
  合成/分卷承担);
  ③ 分段单图上限 `maxPartDeviceH`(默认 12000 设备 px)自动收敛段高。
  分段(v0.4.5)**全程保持同一仿真视口**:预判分段时滚动预热即在拍摄视口下进行
  (虚拟列表高度收敛到拍摄态),循环内探测/滚动/拍摄同口径、同配置 resize 去重跳过,
  每段「滚动定位 → 校验 applied → 渲染稳定 → **截图前复核并锁定滚动位置**
  (v0.4.1:前跳重试/回缩收段)→ 截图」;逐段清除/重建仿真被证明会引发重排涌动
  → 相邻段重复(用户实测),禁止回退到该写法;强制隐藏 fixed。
  拼接/合成在 preview 完成:按各段**实际解码高度**堆叠(dpr 非整数不漂移),
  总高超画布上限时用 `geom.planVolumes` **分卷装箱**(每卷 ≤30000 设备 px、
  每卷一张完整长图),装箱失败才退回逐段列表。
- 图片经 `imagestore` 暂存 SW 内存,preview 分块拉取(每块 512 KB base64),
  TTL 10 分钟 + 最多 3 个 job;绝不把整图塞进单条消息或 URL。
- 下载:`chrome.downloads.download`(blob URL),失败回退 `<a download>`;
  剪贴板仅 PNG,JPEG 在 preview 经 canvas 转码。

## 编辑器(P007,预览页内双状态)

- `preview/edit.js`:preview/edit 双状态 + 矢量标注栈(Store:add/clear 可逆);
  坐标一律存**图像原始像素**系,屏幕换算只发生在渲染瞬间 → 缩放/滚动不错位。
- 渲染:全视口 fixed canvas + rAF 节流重放;马赛克=区域低分辨率降采样 + 笔迹
  destination-in 遮罩(实时与导出同一算法);导出按原始分辨率一次性合成 PNG。
- 不变式:**原图不可变**(标注是叠加层,「还原」一键回原图);无标注时导出直返
  原 blob(零回归)。分卷页每个分卷是独立 target(各自 store/导出)。
- 纯逻辑(`CS.editP` / `CS.Store`)由 `tests/edit.test.mjs` node 测试锁定;
  交互面验收见 P007 §6 人工清单。

## 坐标系纪律(历史高危)

- 跨边界(消息协议)**只允许「文档 CSS px」一种坐标**;视口→文档换算只发生在
  content 的 `pickGet` 一处——document 滚动页用 `+window.scrollX/Y`,内部滚动容器页
  换算到**容器内容空间**(`rect - containerRect + container.scroll`,与 `SCROLL_TO`
  坐标系一致,飞书类页面必用此空间)。
- clip 换算只在 `pipeline.js`,且必须过 `geom.clampClip`(钳制边界按活动滚动容器取)。
- 不信任 CDP 字段名历史(`cssContentSize/contentSize`、`scale/pageScaleFactor`、
  `scrollX/pageX/pageScrollX`),由 `geom.normalizeMetrics` 归一化;
  捕获完整性用 `geom.aspectOk` **宽高比对账**(解 PNG/JPEG 头实测;截断必致比例失真,
  且该结论与 clip 按 CSS px/设备 px 解释无关),不合格自动降级下一捕获路径。
- 真机排障靠 popup 面板「诊断当前页面」dump 原始 JSON(设置页自身是活动标签时会
  取不到目标,故诊断放面板而非设置页),回填 `tests/geom.test.mjs`(详见 CDP 笔记)。

## 错误码与文案

`common/messages.js` 集中定义 `ERR.*` → 中文 `ERR_TEXT`;popup/preview/广播消息只显示
文案,不各自硬编码。新增错误必须走这张表(否则协议测试与 UI 会漏)。

## 已知限制(截至 v0.7.4)

iframe 内元素与跨框整页 · 横向溢出页面 · `chrome://` 等内部页仅支持可视区域截图(注入类模式被 Chrome 安全模型禁止) · 调试横幅无法隐藏
(设计使然) · 剪贴板仅 PNG · 若页面用 JS 轮询恢复被隐藏的 fixed 元素(极小众站点)
会在图里复活 · 固定高度滚动容器(聊天面板类)整页无效,报 `FIXED_CONTAINER` ·
滚动即彻底销毁内容的极端虚拟列表仍可能缺块(飞书类保留占位高度的文档已支持)。
